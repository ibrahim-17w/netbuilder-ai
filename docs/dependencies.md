# Dependency upgrade notes\n\nDependency majors are separate from feature work and from each other where\nthe resolver allows it. This file records the ones that cannot move alone, so\nthe next PR does not rediscover the constraint from a failing `pub get`.\n\n## Done\n\n| Package | From | To | Verification |\n| --- | --- | --- | --- |\n| `cupertino_icons` | 1.x | 2.x | analyze, widget/chat tests, Android debug APK |\n| `flutter_secure_storage` | 9.x | 10.3.1 | analyze, settings/secret tests, Windows release smoke, Android debug APK |\n\nThe secure-storage move is deliberately staged. Version 11 cannot read the\nEncryptedSharedPreferences data written by version 9; its changelog requires a\nversion 10 first run so the custom-cipher migration can happen. Version 10.3.1\nstill supports the current Windows plugin (`win32` 5), so it can ship on its\nown. The deprecated `encryptedSharedPreferences` selector was removed so the\nfirst access performs that migration.\n\n## Blocked on a coordinated `win32` 6 stack\n\nThe following cannot resolve independently on the current SDK:\n\n| Package | Target | Why it cannot move alone |\n| --- | --- | --- |\n| `file_picker` | 13.x | 13 uses `windows_file_picker` 2, which requires `win32` 6 |\n| `share_plus` | 13.x | 13 requires `win32` 6; 12 requires `win32` 5 |\n| `package_info_plus` | 10.x | 9 requires `win32` 5; 10 requires `win32` 6 |\n| `flutter_secure_storage` | 11.x | 11 requires the Windows plugin 4.2.x (`win32` 6) and removes the v9 backend |\n\nA `file_picker` 13 upgrade alone fails because `share_plus` 12 pins `win32` 5.\nAdding `share_plus` 13 then fails because `package_info_plus` 9 pins `win32` 5.\nKeeping secure storage 10 also pins `win32` 5. There is no honest single-package\norder that resolves; the group has to move together.\n\n### Safe order\n\n1. Ship the v10 secure-storage build and let users open it at least once. That\n   performs the key migration while the old backend is still readable.\n2. In one dedicated dependency PR (no feature work), move\n   `flutter_secure_storage` to 11, `file_picker` to 13, `share_plus` to 13 and\n   `package_info_plus` to 10. Record why the four are one PR in the description.\n3. Migrate the file-picker call sites: `FilePicker.pickFile()` is now the\n   single-file API, `pickFiles()` always returns a list, `PlatformFile.bytes`\n   is gone (`readAsBytes()`), and `saveFile()` takes bytes and returns a URI.\n4. Smoke-test Windows release, Android debug and the packaged Windows launch.\n\nDo not use `dependency_overrides` to force `win32` 6 under the old plugins.\nThey compile against the 5.x API and can fail at runtime, which is worse than\nstaying one major behind.\n"})
