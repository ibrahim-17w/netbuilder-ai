## What changed (sidecar/pt_autopilot.py)

| # | Defect | Fix |
|---|---|---|
| F1 | A serial-port probe failure on `HQ_Router` blocked **every** cable on that router, including the unrelated `g0/0 <-> HQ_Switch:f0/1` link, so the router ended with no connections. The interface remap was also applied after the blocked set had been computed. | Blocking is scoped to the exact `(device, interface)` pair (`blocked_ifaces = unavailable | unverified`). A probe failure is recorded as `interface_probe_unverified` and never sets a device-wide interface block. The remap rewrites the cable intent **before** the blocked set is computed, so a remapped WAN link is still wired in the same run. Probe retries are bounded by `_INTERFACE_PROBE_ROUNDS = 3` with a re-focus between attempts. |
| F2 | A failed CLI stage silently cancelled four independent stages (`pc_config`, `server_config`, `security_verification`, and the whole ping/red-link verification), which is why no PC received an IP address. | The `cli_prerequisite_failed` early-`continue`s and the `downstream_blocked` short-circuit are gone. The CLI phase is still reported `failed` (and still fails `validate_run`), but later stages now run and record their own results. |
| F3 | Commands Packet Tracer's IOS emulation does not implement (`time-range`, `crypto isakmp`, `encr`, `hash`, `crypto ipsec transform-set`, `crypto map`, crypto-map sub-mode `set`/`match`, interface-level `crypto map`) were counted as `errors_unrecovered` (26 in one run), which is what made the CLI stage fail. | `_pt_unsupported_reason()` classifies them; `_elide_pt_unsupported()` drops each family together with the sub-mode block that serves it, records one `unsupported_by_packet_tracer` event per family, and appends them to `RUN["unsupported_features"]`. They never touch `errors_unrecovered`, and `validate_run` reports the count without failing on it. |
| F5 | CLI mode desync: `configure terminal` typed inside `(config-if)`; a stray `end` typed at a privileged prompt (Packet Tracer answered `Translating "end"`); a partial line turned the save into `writ write memory`. | Mode-transition lines (`MODE_TRANSITION_LINES`) never use the latched mode - they require a fresh prompt read. `end` is a no-op at a verified privileged prompt. `_clear_pending_command()` abandons a pending partial line before the final save, then re-verifies the prompt. |

The Dart validator (`lib/services/validator_service.dart` lines 211-236,
331-336, 339-345) already warns about the serial-module gap, IPsec and
`time-range`, so no Dart change was made.
